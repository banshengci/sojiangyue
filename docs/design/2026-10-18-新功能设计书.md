# 松江阅 · 新功能设计书

> 版本：v1（2026-10-18）
> 范围：三个新功能 —— 按指令重写、玩法结算页、划词问角色
> 前提：全部本地实现，不引入服务端；**不顶数据库版本号（仍为 15）**

---

## 1. 现状盘点

先把"已经有什么"钉清楚，避免重复建设。

| 能力 | 现状 | 关键位置 |
|---|---|---|
| 阅读器 | EPUB/TXT，WebView + foliate-js，排版/翻页/主题/TTS/笔记/书签 | `lib/page/book_player/epub_player.dart`、`lib/page/reading_page.dart` |
| 划词菜单 | 选中后弹菜单；**已在此处触发 `onSelectText` 插件钩子** | `epub_player.dart` 的 `onSelectionEnd` |
| 人物蒸馏 | 人物/关系/世界观/时间线；可指定人物、章节范围、预估 | `character_distill_service.dart` |
| 角色对话 | 单人/群聊、旁观/扮演/入场、分支、记忆折叠、导演动作 | `character_chat_page.dart`、`character_chat_service.dart` |
| 玩法运行时 | 状态量、分幕、暗牌、结局判定 | `gameplay_runtime.dart` |
| 玩法包 | `.sjgame.zip`，可装 6 个新玩法 | `gameplay_pack_*.dart`、`official_gameplay_packs.dart` |
| 插件体系 | 工具/钩子/设置/存储/增强器/规则/临时角色 | `lib/plugin/*` |
| 世界观 | 可锁定为「不可改写」，注入分两段 | `character_persona.dart` |

**明确缺的三块**（本设计书要补的）：

1. 对话只能整轮重来，不能"按我的要求改"；
2. 玩法有始无终——结局只是正文收尾，没有复盘与状态回看；
3. 阅读与对话是两座孤岛——读到一句想追问，只能退出阅读页重新起会话。

---

## 2. 设计原则

1. **本地优先**：不引入服务端、不上传书籍与对话。
2. **不顶数据库版本**：新列走 `_ensureColumn`，新表走 `_ensureBaseTables`（每次打开幂等执行），
   保持 `currentDbVersion = 15`——`DatabaseSyncManager` 靠版本号比较，顶版本会让远端 v15 文件被判"更旧"而拒绝。
3. **提示词可测**：所有注入文本由纯函数生成，单测逐句断言，不靠"看效果"。
4. **只借机制不抄代码**：参考同行产品的交互范式，提示词、实现、命名全部自写。
5. **降级不崩**：缺人物卡、缺章节定位、缺历史数据时，功能退化为可用形态并说明原因。

## 3. M1：按指令重写这一轮

### 3.1 用户故事

> 角色刚才那句太热情了，我想让它更冷淡一点，但不想从头再来。

### 3.2 交互

- 入口：长按角色气泡 → 现有菜单里增加「按我的要求重写」。
- 弹层：一个输入框（占位提示「例如：更冷淡一点 / 别这么快坦白 / 让她先开口道歉」）+ 三个快捷词（更简短 / 更冷淡 / 换个说法）。
- 确认后：撤掉最后一条角色发言，带着指令重新生成。

### 3.3 机制

复用既有 `_regenerate()` 管道，增加一个**临时舞台指令**（不落库、不进历史）：

```
【改写要求】在不改变已发生事实的前提下重写这一段回复。
改写方向：{用户输入}
只调整语气、措辞与节奏，不要新增情节，不要解释你在改什么。
```

- 实现：`CharacterChatService.reply({... String? rewriteInstruction})`，
  非空时在 messages 末尾追加一条 human 消息（与「继续演出」同款做法）。
- 页面侧：`_advanceInstruction` 的同构字段 `_rewriteInstruction`，`_regenerate()` 透传。

### 3.4 边界

| 情况 | 行为 |
|---|---|
| 最后一条不是角色发言 | 菜单项置灰（避免"重写用户自己的话"） |
| 输入为空 | 等价于普通「重新生成」，不报错 |
| 首轮（无历史） | 菜单项不显示 |
| 生成失败 | 保留原回复（回滚到删除前），提示失败 |

### 3.5 验收

- [ ] 长按角色气泡出现「按我的要求重写」
- [ ] 输入指令后，新回复体现指令（人工验证 3 次，2 次以上符合）
- [ ] 无指令时行为与现有「重新生成」一致
- [ ] 单测：指令拼装含改写要求、空输入不产生指令段

### 3.6 工作量

约 0.5 天（1 个提交）：服务参数 + 页面弹层 + 4 个单测。

## 4. M2：玩法结算页

### 4.1 用户故事

> 这局打完了，我想看看过程：哪一步崩的、好感怎么掉的、暗牌到底是什么。

### 4.2 数据缺口与方案

现状：`tb_gameplay_sessions` 只存**当前值**（`stats` / `member_stats` JSON），`log` 存每轮一句话。
**没有历史曲线**。两种方案：

| 方案 | 做法 | 评价 |
|---|---|---|
| A. 新增快照表 | `tb_gameplay_stat_snapshots(session_id, turn, key, member, value)` | 查询与绘图方便；表小（每局 ≤ 轮数 × 状态数） |
| B. 塞进 log | 在 `log` 的 JSON 里带上当轮快照 | 零建表，但要解析整条 log 才能画图 |

**选 A**：建表走 `_ensureBaseTables`（`IF NOT EXISTS`，幂等），**不需要顶版本号**。

```sql
CREATE TABLE IF NOT EXISTS tb_gameplay_stat_snapshots (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id INTEGER NOT NULL,
  turn INTEGER NOT NULL,
  stat_key TEXT NOT NULL,
  member TEXT,              -- 为空表示集体值
  value INTEGER NOT NULL,
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_gp_snap_session ON tb_gameplay_stat_snapshots(session_id, turn);
```

写入点：`_applyGameplayTurn()` 调 `GameplayRuntime.apply()` 之后，逐条落快照。

### 4.3 结算页内容

| 区块 | 数据来源 |
|---|---|
| 结局 | `session.ended` + 最后一轮正文 + `endingHint` |
| 分幕回顾 | `log` 按 `turn` 聚合到各幕（`mode.phases`） |
| 状态曲线 | 快照表（集体值一条线；按人状态每人一条） |
| 暗牌揭晓 | `session.secret`（仅 `ended` 后展示） |
| 分享卡 | 生成一张 1080×1440 PNG（复用既有 `shareFile`） |

### 4.4 降级

- 老对局没有快照 → 显示"本局未记录过程"，只展示结局、分幕回顾与暗牌。
- 暗牌为空 → 整块隐藏（不是显示"无"）。

### 4.5 验收

- [ ] 打完一局可进入结算页
- [ ] 曲线与当轮实际变化一致（单测：apply → 快照 → 回读）
- [ ] 老局（无快照）不崩、有提示
- [ ] 分享卡可导出且文字不截断

### 4.6 工作量

约 1.5 天：建表 + 写入 + 页面 + 曲线组件 + 分享卡 + 6~8 个测试。

## 5. M3：就这一句，问问 TA

### 5.1 用户故事

> 读到「黛玉把花埋了」，我想问她自己那一刻在想什么。

### 5.2 交互

1. 阅读页划词 → 菜单新增「问问 TA」（仅当本书**已蒸馏出人物**时显示）。
2. 点开是一列人物（按本段出现与否排序，最多 8 个）。
3. 选中后进入单人对话，顶部显示来源引文卡片：
   > 「……（选中段落）」——《书名》第 N 章

### 5.3 上下文预算

灌整章会爆。固定为三段：

```
[引文]      选中段落（≤ 200 字，超出截断并加省略号）
[章节]      章节标题 + 前后各 300 字
[人物]      人物卡：身份/性格/所求（取自 CharacterCard）
[世界]      仅锁定事实（pinned），最多 5 条
```

合计约 900~1200 字，可控。

### 5.4 提示词契约

```
读者正在读《书名》，读到下面这一段时想到了你，想听你说说。

【这一段】
{quote}

【上下文】
{contextBefore}
{quote}
{contextAfter}

请以「{人物名}」的身份回应读者：说的必须是这个人此刻会说的话，
可以承认、可以否认、可以回避；不要总结这段写了什么，也不要替作者解释。
```

关键约束是最后一句——不加的话，模型九成会写成"这段文字表达了…"的赏析。

### 5.5 数据流

- 会话仍走 `CharacterChatSession`（单人模式），**不新增表**。
- 引文与章节：作为首条 `narrator` 消息落库（与"开局情境"同款），
  这样历史里能看到"这一轮是从哪句开始的"，重开也对得上。
- 传参：`CharacterChatPage(entryQuote:, entryChapter:)` 两个可选参数，仅新建会话时使用。

### 5.6 边界

| 情况 | 行为 |
|---|---|
| 本书没有人物卡 | 菜单项不显示（避免点进去一片空白） |
| 选中 < 2 字 | 不触发（沿用现有经验：2 字起） |
| 章节定位失败 | 只带引文，不报错 |
| 该人物卡为空字段 | 跳过对应段落 |

### 5.7 验收

- [ ] 划词 → 选人物 → 进入对话，首条旁白含引文
- [ ] 回复是"角色口吻"而非"文本赏析"（人工验证 5 次，4 次以上符合）
- [ ] 无人物卡的书不显示入口
- [ ] 单测：上下文拼装长度上限、裁剪规则、空字段跳过

### 5.8 工作量

约 2 天：菜单项 + 人物选择 + 参数传递 + 旁白落库 + 提示词 + 6~8 个测试。

## 6. 数据库影响汇总

| 变更 | 方式 | 是否顶版本 |
|---|---|---|

## 8. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 提示词漂移 | M3 变成"文本赏析" | 契约里写死否定项；用 5 次人工抽检卡门 |
| 上下文超预算 | 长章节把 prompt 撑爆 | 硬截断（引文 200 字、前后各 300 字），单测覆盖 |
| 快照表膨胀 | 单局轮数大时行数多 | 每局行数 = 轮数 × 状态数；一局上限 10 幕，可控；必要时按会话删除时级联清理 |
| 老数据不兼容 | 老对局无快照 | 结算页降级提示，不补算（补算等于编造） |
| 误删原回复 | 重写失败后原话丢了 | 先备份最后一条，失败则回滚插入 |

## 9. 测试策略

| 层次 | 内容 |
|---|---|
| 纯函数单测 | 指令拼装、上下文裁剪、快照回读、结算数据组装 |
| DAO 测试 | 用 `BaseDao.useDatabaseForTest` 起内存库，验证建表幂等与快照读写 |
| 契约测试 | 玩法包/插件已有的契约测试不回归 |
| 人工验证 | M3 的角色口吻、M2 的曲线正确性——这两项单测替代不了 |

门禁：`flutter analyze --fatal-warnings --fatal-infos` 零问题 + `flutter test` 全绿。
**注意**：`dart analyze` 本轮出现过漏报（报 No issues 但有 13 个 error），门禁只认 `flutter analyze`。

## 10. 明确不做

| 不做 | 原因 |
|---|---|
| 多人在线协作 | 无服务端，成本极高 |
| 书城 / 推荐 | 与本地阅读器定位冲突 |
| 玩法排行榜 / 社交 | 没有数据基础，做出来是空的 |
| 云端同步对话 | 隐私面增加，且收益不明 |
